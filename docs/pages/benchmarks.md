# Benchmarks

All numbers on this page are reproduced from the committed benchmark outputs
([`bench/results.md`](#brouwerzimmermann-cpu-gpu-vs-the-reference) and
[`bench/cc_results.md`](#connected-cluster-vs-bz-vs-the-reference)). They are measurements,
not estimates. The reference throughout is the
[`codeDistance` / `codeDistancePYPI`](https://github.com/m-webster/codeDistancePYPI)
package — `BZDistMW` is its Brouwer–Zimmermann, `connectedClusterMW` its connected cluster.

### Summary

- Backends available on the benchmark machine: `['cpu', 'gpu']`.
- **`default(BZDistMW) / gpu` speedup**: min 0.4×, **max 235.4×**, median 8.5× (over the
  13 codes where the reference finished).
- **`cpu / gpu` speedup**: min 0.32×, max 2.32×, median 1.39× — values below 1 mean the
  CPU was faster, which is expected for small codes where GPU dispatch overhead dominates
  (the hybrid dispatcher is what keeps the GPU from being a net slowdown).
- The reference **timed out** (>30 s) on toric L=8 — qubitserf solved it.
- **All distances matched**: qubitserf-CPU equals the reference `BZDistMW` on every code
  where the reference finished, and GPU's best-of-retries value equals the CPU value
  everywhere.
- Beyond the table, the README reports GPU as **up to ~500×** faster than the default
  reference across the broader suite.

#### GPU determinism

GPU was run 3× per code as a determinism probe and returned the **same correct distance
every time** on all codes. (An earlier stale-device-buffer bug — the buffer cache keyed on
host-pointer identity — was fixed by keying on a unique per-solve token.) A `*` would flag
any code whose GPU runs disagreed; there are none. Reported GPU times are the fastest
of the probe runs.

## Connected cluster vs BZ vs the reference

Generated by `bench/cc_benchmark.py`. `cc` is qubitserf connected cluster; `bz` is qubitserf
Brouwer–Zimmermann (capped on hard codes, shown as the rigorous `[lower, upper]` bracket);
the reference shows both its BZ (`BZDistMW`) and its connected cluster
(`connectedClusterMW`).

| code | n | d | qubitserf cc | qubitserf bz | ref BZDistMW | ref connectedClusterMW |
|---|---|---|---|---|---|---|
| steane [[7,1,3]] | 7 | 3 | d=3 (1.4ms) | d=3 (245us) | d=3 (3.3ms) | d=3 (816us) |
| shor [[9,1,3]] | 9 | 3 | d=3 (824us) | d=3 (274us) | d=3 (1.4ms) | **d=0** (741us) |
| toric L=6 [[72,2,6]] | 72 | 6 | d=6 (1.1ms) | d=6 (2.1ms) | d=6 (239.6ms) | d=6 (5.3ms) |
| surface L=6 [[61,1,6]] | 61 | 6 | d=6 (1.0ms) | d=6 (3.1ms) | d=6 (140.7ms) | d=6 (3.8ms) |
| bb [[72,12,6]] | 72 | 6 | d=6 (1.2ms) | [6,6] capped (3.2ms) | d=6 (1.10s) | d=6 (32.3ms) |
| toric L=9 [[162,2,9]] | 162 | 9 | d=9 (1.9ms) | [7,9] capped (6.02s) | >30s (timeout) | d=9 (157.5ms) |
| toric L=10 [[200,2,10]] | 200 | 10 | d=10 (2.5ms) | [8,10] capped (27.51s) | >30s (timeout) | d=10 (522.5ms) |
| **gross [[144,12,12]]** | 144 | 12 | **d=12 (377.6ms)** | [8,12] capped (3.87s) | **>30s (timeout)** | **>30s (timeout)** |

### Takeaway

- On sparse codes whose BZ lower bound is weak (bivariate-bicycle, large toric), qubitserf's
  connected cluster certifies the exact distance in well under a second, while
  Brouwer–Zimmermann (qubitserf's *and* the reference's) cannot prove it in tractable time.
  On small codes all methods agree.
- qubitserf's CC is the **same algorithm** as the reference's `connectedClusterMW`, but a
  compiled, seed-parallel implementation: **tens to hundreds of times faster** (toric
  L=10: 2.5 ms vs 522.5 ms, ≈209×), and it certifies the gross code `[[144, 12, 12]]` in
  **~0.4 s** (377.6 ms) where the reference's own connected cluster **times out (>30 s)**.
- qubitserf's CC also returns the correct `d=3` for the Shor code, where the reference's
  `connectedClusterMW` reports a spurious `d=0`.

## Reproducing the benchmarks

All scripts run from the repository root. The reference comparison needs the
`codedistance` package (installed, or cloned on `PYTHONPATH`); the scaling and gross-code
scripts do not. Use whichever Python has the package and NumPy available; on the project's
machine that is the `sage_env` interpreter:

```bash
# BZ: CPU / GPU vs the reference BZ -> writes bench/results.md
PYTHONPATH=python python bench/benchmark.py

# connected cluster vs BZ vs the reference -> writes bench/cc_results.md
PYTHONPATH=python python bench/cc_benchmark.py

# qubitserf on toric/surface codes beyond the reach of the reference -> bench/scaling.md
PYTHONPATH=python python bench/scaling.py

# the IBM gross code [[144,12,12]]: BZ bracket vs CC certification
PYTHONPATH=python python bench/gross_code.py
```

Notes:

- The reference is invoked in a **subprocess with a hard timeout** (`bench/_ref_runner.py`,
  default 30 s) because it can hang or run for minutes on larger codes; once a method
  exceeds the timeout for one size it is skipped for all larger sizes in the same family.
- The reference package path / timeout can be overridden via environment variables
  (`REF_TIMEOUT`, and `BZ_CAP` to cap qubitserf's BZ on hard codes so it can't hang).
- GPU is run several times per code as a regression guard; the script flags any
  disagreement and reports the fastest run.
- Absolute timings depend on your hardware; the **distances** and the relative orderings
  are what the benchmarks assert.
